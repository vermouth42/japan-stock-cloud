# keiba — 回収率100%超を目指す競馬予想システム

## 結論: 「最適解」の構造

控除率 (単勝 20%) がある以上、**的中率を上げても回収率は100%を超えません**。
1番人気を買い続けても約80%、全馬均等買いなら約75%です。
回収率を100%超にするための答えは次の1式に集約されます。

```
買う条件:  P_自分(勝つ) × オッズ  >  1 + 安全マージン
```

つまり「強い馬」ではなく **「市場(オッズ)が過小評価している馬」だけ** を買う必要があります。
そのため本システムは以下の5段構成です。

| 段 | 役割 | 実装 |
|---|---|---|
| ① 多ファクター特徴量 | 市場が織り込みきれない情報を数値化 | `features.py` |
| ② ファンダメンタルモデル | オッズを使わず勝率を推定 | 条件付きロジット (`model.py`) |
| ③ **市場融合 (Benter法)** | オッズの集合知とモデルを最適に合成 | `P ∝ exp(α·u + γ·log q)` |
| ④ 期待値 + ケリー | 期待値の高い馬だけ、優位性に比例した額を賭ける | `betting.py` |
| ⑤ ウォークフォワード検証 | 未来情報ゼロで真の回収率を測る | `backtest.py` |

最大のポイントは ③ です。自前モデル単体はオッズ(市場)より精度が低いのが普通ですが、
「市場確率を事前分布にし、モデルが市場と異なる部分だけ上乗せする」と、
市場単独より確実に精度が上がり、その差分が期待値プラスの源泉になります
(香港で巨額の利益を出した Bill Benter の手法)。

## ファクター (6群・36変数)

全て **そのレースより前の日付の情報のみ** で計算します (テストで保証)。

| 群 | 内容 |
|---|---|
| ability 能力 | スピード指数 (コース・距離別基準タイム、クラス補正済み馬場差で補正) の前走/近5走平均/最高/指数加重、上がり3F相対値、着順率、複勝率 |
| aptitude 適性 | 芝ダ・距離帯・コース・道悪での自己実績差、好走距離と今回距離のズレ、父の芝ダ別/距離帯別 A/E、父産駒の好走距離とのズレ |
| connections 人 | 騎手・調教師・騎手×調教師の A/E (実勝利/期待勝利)、**市場比 A/E** (オッズ以上に勝つか)、乗り替わりによる騎手格上げ |
| condition 状態 | レース間隔、半年以上の休み明け、馬体重増減とその絶対値、キャリア、年齢、牝馬、斤量 |
| context 条件替わり | 昇級・降級、距離変更幅 |
| pace_draw 展開・枠 | 脚質 (近5走の最終コーナー位置)、脚質×ペース圧力 (先行馬の多さ)、コース別枠順バイアス |

設計上の工夫:
- 条件付きロジットはレース内の相対比較しか効かないため、馬ごとの値は **レース内 z スコア** に変換。
  レース共通の条件 (ペース・道悪) は馬の値との **交互作用** で投入。
- 騎手・種牡馬などの率は少サンプルで暴れるため **ベイズ縮約** (`(実績+k)/(期待+k)`)。
- 係数は L2 正則化付きのニュートン法で厳密に最尤推定。

## 買い方

- `EV = p × odds ≥ ev_min`, `p ≥ min_prob`, `odds ≤ max_odds` を満たす馬のみ単勝。
- 賭け額は **1/4 ケリー** (1レース上限は資金の10%)。フルケリーは推定誤差に弱いため。
- 閾値は「過去のアウトオブサンプル予測」で **ROI の下側信頼限界 (平均−1σ/√n)** を最大化して決定。
  単純な ROI 最大化は少数の大穴的中に過学習するため避ける。
- 連系馬券用に Harville 式 (+ 2・3着の平滑化補正) の馬連・複勝確率も用意 (`betting.py`)。

## 検証結果 (合成データ)

`python -m keiba demo` の出力 (JRA 相当の年間約3,400レース × 6年、最初の2年は学習のみ):

| 指標 | 値 |
|---|---|
| 参考: 全馬均等買い | 74.9% |
| 参考: 1番人気買い | 80.3% |
| **本システム 均等買い ROI** | **118.1%** (95%CI 105.3%〜131.5%, 2,300点) |
| 的中率 | 16.2% |
| 対数尤度 (市場比) | 8期間すべてで市場単独を上回る |
| 頑健性: オッズ 5% 悪化を仮定 | 115.7% (95%CI 103.3%〜128.6%) |
| 頑健性: 別の乱数世界 (seed=7) | 110.4% (95%CI 101.6%〜119.4%) |
| 1/4ケリー 最大ドローダウン | 約53〜58% |

ファクター群アブレーション (外すと失われる尤度) では **aptitude (適性・血統) が最大の源泉**、
connections は市場に既に織り込まれているため単独では寄与がほぼゼロ — という結果でした。
実データでも `backtest` を実行すると同じ表が出るので、**効かないファクターを削る判断材料** に使えます。

## ⚠️ 重要な注意

1. **合成データの結果は「仕組みが正しく動く」ことの証明であって、実際に儲かることの証明ではありません。**
   合成市場には意図的に「適性・枠・展開の過小評価」という歪みを入れてあり、モデルはそれを発見しています。
   実際の JRA 市場がどの程度効率的かは、実データでの `backtest` でしか分かりません。
2. 実データでは最低でも **5年分以上 (約17,000レース)** を推奨。データが少ないと優位性は検出できません。
3. 検証は **最終オッズ** で行っています。実際の購入は締切前のオッズなので `--slippage 0.05` 等で
   悪化を織り込んで、それでも 100% を超えるかを確認してください。
4. ケリー基準でも最大ドローダウン 50% 超はあり得ます。資金は失ってよい額に限定してください。
5. 95% 信頼区間の **下限** が 100% を超えるまでは実弾投入しないのが原則です。

## keiba_app の keiba.db で使う (実データ)

`keiba` フォルダを `C:\Users\naynu\Desktop\keiba_app` にコピーし、そのフォルダで実行します
(DB には SELECT しか発行しません。長い集計の間は app.py を止めてください)。

```powershell
python -m keiba dbcheck  --db keiba.db                    # 年別の件数・列の充足率を確認
python -m keiba backtest --db keiba.db --out bets.csv     # ウォークフォワード検証
python -m keiba backtest --db keiba.db --slippage 0.05    # オッズ5%悪化を想定
python -m keiba predict  --db keiba.db --optimize         # 結果未確定レース (出馬表) の買い目
```

`sqlite_loader.py` が引き継ぎ資料の構造を次のように扱います。

| DB の事情 | 対応 |
|---|---|
| `entries.horse_id` が馬名 | 同名馬の混同を避けるため「馬名_生年 (開催年−年齢)」をキーにする |
| `class` の表記ゆれ ('1勝クラス'/'500万下' 等) | 0〜4 の5段階に正規化。障害は除外 |
| 確定オッズは 1986 年から全期間そろっている (dbcheck で確認) | 既定で全て使う。2015 年以降を読み込み、賭けの検証は 2017 年以降の約10年分。古い期間を外したいときは `--odds-since` |
| 読み込み開始日 | 既定 2015-01-01 (`--since`)。さかのぼるほど遅くなる (2015〜で数分) |
| 調教師が 2022 年以降は空、父が 2022 年以前はほぼ空 | 不明は中立 (レース内平均) 扱い。該当ファクターはデータのある期間だけ効く |
| `finish_position` が NULL/0 | オッズ無し=取消・除外として除外。オッズ有り=競走中止・失格として**最下位扱いで残す** (除くと残りの馬の期待値が水増しされ、回収率が過大に出る) |
| 出走馬の行が欠けたレース | Σ(1/オッズ) が 1.12〜1.45 を外れるレースは賭け・市場融合の学習から除外 (`dbcheck` の `bad_mkt` 列で割合を確認) |
| `passing_order` '3-3-(2)-*1' | 数字だけ拾い最後のコーナー順位を使用 |
| 馬体重増減が 2025 年以降のみ | 欠損はレース内平均扱い (0) |
| 出馬表の単勝オッズ | `entries.odds` が空なら `odds_snapshot` で補う |
| 資料と実物の列の差 | 無い列は NULL として読む |

注意: `entries.odds` は**確定オッズ**です。`odds_history` (2026-11-07〜蓄積中) がたまれば、
「購入時点のオッズ→確定オッズ」の悪化幅を実測して `--slippage` に反映できます。

## 使い方

```bash
pip install numpy pandas            # 依存はこれだけ
python -m keiba demo                # 合成データで全工程を実演
python -m keiba backtest --data races.csv --slippage 0.05 --out bets.csv
python -m keiba predict  --data races.csv --card today.csv --optimize
python -m pytest tests              # 未来リーク検出テスト等
```

### データ形式 (`races.csv`, 1行=1頭)

`race_id, date, course, surface(turf/dirt), distance, going(0良〜3不良), race_class(0〜4),
horse_id, horse_no, age, sex(M/F/G), weight_carried, body_weight_diff, jockey_id, trainer_id,
sire_id, odds_win, finish_pos, time_sec, last3f_sec, corner_pos`

日本語ヘッダ (`日付, 馬番, 騎手, 単勝, 着順, タイム(1:34.5形式可), 通過(3-3-2形式可), 馬場(良/稍/重/不)` 等)
も自動変換します (`schema.py`)。出馬表 (`today.csv`) は結果列 (着順・タイム等) が無くて構いません。
データは JRA-VAN Data Lab. 等の正規ルートで取得してください。
