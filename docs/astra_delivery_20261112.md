## 追加した通知送信箱

- 候補の資金予約と通知待ちレコードを同じSQLiteトランザクションで保存。片方だけ失敗すると両方をロールバック。
- 同一イベントの重複登録、別ワーカーによる二重送信を防止。
- 送信前に有効期限と予約の有効状態を確認。期限切れは送信せず、本人が解放した予約は取消扱い。
- 配信側が「未受理」と確定した失敗だけ、同じイベントIDで最大3回、2秒・4秒の間隔で再試行。待機中に期限切れなら送信しない。
- タイムアウト・不明な応答・送信途中のプロセス停止は「不明」。送達済みの可能性があるため自動再送しない。
- 送信中の停止は30秒経過後に不明へ移す。定期的なrecover_interrupted呼出しと状態監視は配備側で必要。
- 送信失敗・期限切れでも資金予約は勝手に戻さない。予約の本人解除画面は未実装。
- 状態は ready / sending / accepted / expired / cancelled / failed / uncertain。
- accepted は配信業者が受理したことだけ。iPhone到達・本人既読・注文・約定は示さない。
- 現在の通知文面は「検証用候補・実戦GO未解禁」。go_allowed=falseを維持。

送信アダプターは注入する関数であり、この実装に実宛先や認証情報は含めない。5秒以下の通信タイムアウト、固定された本人宛先、idempotency_keyの利用、期限表示を実配信側でも実装する必要がある。HTTP本文から宛先・予算・ランク・板OKを受け入れない。

9ケースを追加し、ローカル全112テスト成功（4.445秒）。異常時の原子性、再起動、別接続からの競合、確実な失敗と不明な失敗、期限、本人解除、B判定の除外を検証。これは擬似配信アダプターによる検証で、実WebhookやiPhoneへの送達試験ではない。

## 本番までに必要な接続

1. TradingViewのHTTPSクライアント証明書を検証できる受信先。証明書の文字列だけでなく検証済み証明書チェーンを使う。受信は永続化後すぐ応答し、照合と通知は別処理にする。
2. 予算・ランク・損切りのSheet読取接続、調査範囲の分かるイベント接続。
3. 必須条件である板OKを判定できる正規データ経路。価格/VWAPだけで板を代替しない。
4. 本人宛の配信接続と実条件からiPhone到達までの確認。

受信先のホストと板情報取得サービスは未選定。契約・課金を勝手に行わない。既存のGoogle Sheets・GitHub Actionsだけで認証済みリアルタイムWebhookサーバーが稼働したとは扱わない。
