# Pine v6・Ver.7.5統合実装計画

> 2026-11-11 要件更新：勤務中の本人入力を必須としない。分析・候補選定・条件判定・通知・保有監視を自動化し、SBIの実注文操作だけ本人が行う。下記の手動確認方式は既存の暫定実装であり、最終仕様の完成とは扱わない。最新の完成条件は `astra_automation_scope_20261111.md` を優先する。

## 役割

| 層 | 担当 | 扱う判定 |
|---|---|---|
| GitHub/既存シート | 全100銘柄の日足、材料、A/A+、市場日/整合性 | 監視対象と売買候補資格 |
| TradingView/Pine | 選抜銘柄の当日価格、VWAP、確定足の技術条件 | SBIを確認するための候補通知 |
| 最終チェック | 当日SBI現在値/VWAP/板、イベント、現金、保有分込み損失予算 | 条件がそろった場合だけ手動発注候補 |
| SBI証券 | ユーザー本人 | 手動発注・損切り設定 |

PineからGoogle Sheets/任意HTTP APIを直接読む前提を置かない。候補版のA/A+は手動入力の仮接続であり、シートとの自動同期は未完成。SBIの板をPineが確認済みにすることもない。

## 段階と合格条件

| 段階 | 作業 | 合格条件 |
|---|---|---|
| 0 監査 | 対象SHA・全100銘柄・数式・PRを読む | 不具合と未確認を記録。今回実施 |
| 1 隔離基本版 | 候補通知Pine、研究用Pine、共通安全条件 | 2本のコンパイル確認済み。候補版1分/5分足表示・初期停止、研究版模擬取引確認。実通知・全異常系の場中検証は未完了 |
| 2 データ復旧 | 確定日フィルタ、休日、再取得/指数バックオフ、原子的保存 | 平日朝/昼/夜・連休・1銘柄欠損・重複の再現テスト。失敗時は前回ファイル保持 |
| 3 シート整合 | 100行参照、イベント営業日、全GO経路の共通化、現在値株数 | コピー上で旧画面経由も条件不足ならGO禁止。銘柄並べ替え時に確認値を持ち越さない |
| 4 技術実験 | ベースラインに1指標ずつ、次に複合を追加 | 試した全条件を記録し、未使用期間・費用後で改善を比較 |
| 5 マクロ | 発表/観測可能時刻を保存し時刻結合 | 日本市場時点で未公表の米国終値・統計改定値を使わない。欠損時は未確認 |
| 6 9条件検証 | デイ/スイング/併用 × 3リスク条件 | 同一データ・共有資金・含み損益込み・100株・費用・全取引台帳 |
| 7 通知 | 少数銘柄で端末実測→対象拡張 | iPhoneのロック中通知、時刻、重複、期限切れ、損切り通知を確認 |
| 8 本番連携 | コピーから段階移行・切戻し可能に | 100銘柄維持、朝/引け後の既存処理維持、ユーザー手動注文のみ |

## 技術指標の実験順序

基本セットはVWAP・出来高・ブレイクアウト・ATR。移動平均/EMA、RSI、MACD、ボリンジャーバンド、OBV、ローソク足、ギャップ、支持抵抗、相対的強さを個別に追加して評価する。全部を一度にAND条件にしない。

- ブレイク水準は当日を除く過去高値。支持抵抗/pivotは確定した時点から有効にし、過去に遡ってシグナルを置かない。
- ATRは旧SMAとWilderを区別。数値差と株数差を確認してから移行。
- 出来高は前期間平均を分母にし、時間帯季節性（寄付き/昼休み/引け）を評価。現行基本版は単純比較で研究段階。
- スイングの正式検証でも新規約定時に当日VWAP条件が必要。日足のみの研究を正式スイング成績にしない。
- マルチ時間足では確定足を使用。TradingView上で再読込前後とリアルタイム通知を比較する。

## マクロ・イベント

SOX、NASDAQ100、S&P500、日経平均、TOPIX、USDJPY、米国金利、VIXは「環境表示」から開始。銘柄別/業種別の相関をローリング推定し、フィルター採用の有無を未使用期間で比較する。ETFを指数代用にした場合は明記する。

各観測に `observation_time`, `available_at`, `source`, `revision` を持たせる。米国休場・日米夏時間差・時差を扱い、日本のシグナル時刻以前に公表された値だけを結合する。Pineの単純な日付一致や日足[1]だけで米国前夜の最新確定値を正しく取り込めたと判断しない。

雇用統計・CPI・FOMCは発表日時と公表時点の値を記録。将来の改定値や事後に分かった予想値を使わない。イベントの「3営業日以内」はJPX営業日で統一し、未登録を安全と解釈しない。

## 正式バックテストの仕様

| 条件 | 1取引の許容損失 | 同時に許容する予定損失合計 | 総建玉金額 |
|---|---:|---:|---:|
| 保守型（暫定研究値） | 0.5% | 1.5% | 純資産100%以下 |
| 積極型（暫定研究値） | 1.0% | 3.0% | 純資産100%以下 |
| 高リスク型（暫定研究値） | 1.5% | 4.5% | 純資産100%以下 |

数値は比較実験の仮定で推奨設定ではない。現行シートの1取引1.5%は変更しない。信用はSBI資格・銘柄規制・当日の条件を別途確認できるまで実装に含めず、将来の信用シナリオは金利/貸株料/逆日歩等を別計上する。

- 100万円から開始し、買付余力・100株単位・未決済含み損益・部分約定・流動性を考慮。デイとスイング併用では資金を二重計上しない。
- 当時の監視対象とA/A+を再現できる履歴がなければ「技術条件のみ」「現100銘柄固定」の参考ラベルを必須にする。
- シグナル確定後の翌足約定を基本とし、取引停止、値幅制限、ストップ飛越、引け約定の可否を検証する。
- 手数料・スプレッド/スリッページ、必要なら信用コストを別々に記録。SBIの実契約費用とストレス費用を分ける。
- 学習→検証→最終未使用期間を時系列で分離。保有期間の重なりを除くpurge/embargoを設定。すでにPRの調整に使った期間は「完全未使用」と呼ばない。
- 勝率、円とR両方の期待値/PF、日次時価資産の最大DD、年率、月次、3か月ローリング収益、破産/資金不足率を報告。
- 10倍到達は3か月内の到達件数/評価窓数をまず示す。窓の重複と不確実性を明記。ブロック再標本化は仮定付き推定として扱い、将来の保証や安定確率と呼ばない。
- パラメータ、コードSHA、データ版、費用、期間、除外理由、全取引を保存して再現可能にする。

## データ契約と通知制約

J-Quantsは未契約のまま進める。契約する場合はその時点の公式規約とプラン条件で、契約終了後の保持/削除範囲、派生物、バックアップを確認する。保存可を推定しない。認証はSecrets等に限定し、コード/チャット/ログには出さない。

Essentialの実アカウントのアラート枠・リアルタイム権限は未確認。100銘柄の全体監視をGitHub/シートに残し、TradingViewはA/A+上位候補の個別通知から始める。1本のPineが100銘柄を無制限に要求できる設計にはしない。

TradingViewのアラートは作成時のコード/入力のコピーで動く。毎日変えるA/A+、銘柄、確認日、株数をチャート上だけ更新しても既存通知へ自動反映されないため、現基本版は通知の再作成が必要。完全自動連携は別工程で可否を検証する。

## 次回のTradingView検証手順

1. 候補版をPine Editorで保存/チャート追加し、コンパイル結果を記録。標準TSE1分/5分足でVWAPと前日200日線を目視照合。
2. 通知初期OFF、確認日初期0のまま通知なしを確認。研究版も初期OFF。
3. 研究版を日足で実行し、最初の約定がシグナル翌足か、100株単位か、ブラケットが約定時から存在するかを一覧で確認。仮定コストを記録する。
4. 再読込・時間足変更・銘柄変更・B/C・翌日・株数0・イベント未確認を試す。候補版はリアルタイムだけなので履歴マークが出ないことは仕様。
5. 通知は候補版のalert()のみ、iPhoneアプリ通知を選択。Webhook/証券連携は設定しない。実機到達が確認できるまで通知完成とは報告しない。
