# 自動データ照合の試験版

`astra/automatic_preflight.py` は、本人が毎回価格や確認日を入力する旧ゲートから切り離した、新規現物買いのオフライン検証器。出典をTradingView価格・Ver7.5候補・イベント・SBI口座・板提供元の5系統に分ける。本番や通知への配線、データ取得、発注は含まない。

## 入力の契約

各Evidenceは銘柄、出典、元の観測時刻、受信時刻、有効期限、参照ID、値を持つ。受信時刻の更新だけで古い価格を新しい価格と扱わない。未来時刻・時系列逆転・タイムゾーンなし・前日観測・期限切れ・未知の項目を拒否する。

| 入力 | 必須内容 | 暫定の鮮度上限 |
|---|---|---:|
| TradingView | 価格・VWAP・出来高継続・上ヒゲ・ギャップ | 90秒 |
| Ver7.5 | 当日A/A+・推奨株数 | 8時間かつ当日 |
| イベント | 個別・マクロ確認範囲、今後3JPX営業日までの網羅期間、重要予定日 | 30分 |
| SBI口座 | 注文済み分を控除した余力・残余リスク・実保有・買い/売り未約定・取得範囲の完全性 | 30秒 |
| 板提供元 | 銘柄に対応する板判定 | 10秒 |

鮮度上限は仮仕様であり、提供元の配信保証を実測した数値ではない。価格・板・口座の観測時刻が15秒を超えて離れている場合も停止する。最短の証拠期限、鮮度上限、候補時間帯の終わりを判定期限とする。

同期情報は `sync_audit.audit` の結果を渡す想定。当該評価時点の期待日足日付・100銘柄・4500行・重複0・監査理由空を要求。入力ラベルや真偽値が一致しても、出典の真正性・完全性の証明にはならない。実アダプターを認証・検証する工程は残る。

## 計算と停止

- A/A+以外、推奨100株未満・単元不一致、重要予定が3JPX営業日以内、VWAP未満、損切りや許容損失未設定は停止。
- 株数は推奨上限・許容損失と残余リスク・現金余力の小さいものから100株単位で再計算。往復費用余裕を1株当たりに加算。通貨計算はDecimalを使用。
- 保有・未約定がある銘柄は重複エントリーを停止。買い増し・信用・空売り・保有売却は未対応であり、この試験版の合格をその許可にしない。
- 取得不明の値をゼロやOKに補完しない。初期資金100万円を現在余力と仮定しない。
- 合格時も `go_allowed=False`。検証器は本番GO、注文、プッシュ配信を一切行わない。

## 検証

新規13テスト（各テスト内に複数の停止ケース）。完全な合成入力で100株・予定損失5200円になる正例を含むが、正式GOは常にfalse。欠損、出典/銘柄不一致、古い値の再受信、未来/期限切れ時刻、B/C、数量、技術条件、保有/未約定、祝日を挟む3営業日、価格/費用/余力、同期不整合を確認する。

これらは実相場バックテストではない。勝率、PF、10倍到達確率の根拠にしない。

## 本番化の前提

1. 各データを許可された方法で取得するアダプターと欠損・遅延・認証の実測。
2. TradingViewデータの用途が契約上認められることを確認。公式MCPの接続だけで外部の無人判断・リスク管理・蓄積利用が許可されるとは扱わない。個人向け表示の例外は限定的。[公式規約](https://www.tradingview.com/policies/)
3. A/A+履歴、イベント取得範囲、板判定、SBI余力/未約定/約定の追随を監査。
4. 注文を行わない場中照合、失効・重複通知・データ停止・再起動・翌営業日を含む連続試験。
5. 本番の手動確認フラグへ自動代入して検証を省略しない。

## SBIの取得経路の確認（2026-11-11）

[HYPER SBI 2公式操作ガイド](https://search.sbisec.co.jp/v2/popwin/guide/tool/hyper_sbi_2/05_trading/ck_orderstatus.html)で、未約定・注文照会・約定履歴とCSVエクスポートを確認。注文照会は自動更新されないとの説明がある。これは画面操作/CSV機能の確認であり、クラウドからの常時自動取得が確認できたわけではない。

公開資料から国内株の保有・余力・未約定を自動取得できる接続先は確定できていない。「APIが絶対にない」とは断定しない。未確認のRSSや非公開APIを推測して接続せず、パスワードをコードや成果物に保存しない。現物・信用・NISA・口座区分や約定/取消の遅延を実確認する前に本番へ接続しない。
