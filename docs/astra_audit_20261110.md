## PR #1 バックテストの信頼性

既存Pythonテスト23件はこの環境で再実行して全件成功。これはコードの既存テストが通ることの確認で、成績・データ品質・実戦一致を証明するものではない。

PR記載の勝率36.4%、PF1.28、年率8.0%、最大DD33.9%は**過去PRの申告値**。長期データ/取引一覧を取得して数値再現はしていない。対象期間2017-08〜2026-10は約9年2か月であり、厳密な満10年とは異なる。

採用できる部品：指標計算の単体テスト、翌足始値約定、同一日内で損切り/利確両方に触れた際の損切り優先、ストップを飛び越えた場合の始値約定、銘柄別/年別集計の枠組み。

正式実戦成績に使えない理由：

1. 現在選んだ100銘柄の遡及検証。上場廃止銘柄や当時の監視対象を含むpoint-in-time集合ではない。
2. 当時のA/A+、材料公表日時、SBI板/当日VWAP確認、重要イベント確認の履歴がない。Pythonはスイング技術セットアップでありVer.7.5全ルールの再現ではない。
3. `simulate_portfolio`は100株単位と現金による建玉金額制限を考慮しない。初期値は300万円で、本依頼100万円とも違う。
4. 資産曲線は決済損益だけ。未決済の含み損益を除外するので、最大DDが実際より小さくなる可能性がある。
5. Pythonの部分利確は割合。100株を50株ずつ決済する計算になり得るが、Pineは単元未満を切り捨てる。結果が一致する前提を置けない。
6. 翌日ギャップ約定でもRの分母はシグナル日のATR幅で固定。実際の約定価格から損切りまでの損失・株数とは一致しない。
7. Pythonの手数料は0固定。スリッページは円単位、Pineはティック単位。部分利確時の約定・費用も統一が必要。
8. Pythonのトレーリングは前回ストップではなく初期ストップと当日ATRから更新。ATR急上昇時にストップが後退する可能性があり、Pineとの比較が必要。
9. 200日線のON/OFFなどを同じ全期間の結果で選んでいる。未使用期間での確認がなく、過剰最適化の評価が未了。
10. マクロ/財務欠損時に通す実装がある。PR Pineの決算回避は予定日時依存で過去履歴の代替にならない。財務フィルターを含むPineとPythonは同条件ではない。

したがって、10倍到達確率やデイ・スイング・併用の9条件比較は現在「未算出」。技術条件だけの結果から実戦の到達確率を推定しない。
