# 勤務中の入力を必要としない運用への要件更新

2026-11-11、本人は市場時間中に勤務しているため、発注・利確等のSBI注文操作のみ手動とし、その他を通知まで自動化する指示を受領。

> 追加指定：価格情報はTradingView主軸、SBIは注文主軸。価格とVWAPを毎回SBIへ転記する条件は完成仕様から外す。詳細は `astra_tradingview_primary_20261111.md`。

## 完成条件

- 100銘柄監視、日足同期、朝ブリーフ、引け後チェックを維持。
- 当日のA/A+資格、銘柄、価格、VWAP、出来高継続、上ヒゲ、ギャップ、板、重要イベントを出典・観測時刻付きで自動取得・評価。
- SBIの余力、保有、未約定、約定情報と許容損失設定を利用し、損切り・株数・残余リスクを算出。初期方針は事前設定できるが、毎回の手入力を通常動作の前提にしない。
- 買い候補、利確、損切り、データ停止を自動通知。発火時刻、配信結果、重複・失効を記録。
- 本人はSBIで注文を実施。システムは注文送信・変更・取消を行わない。約定・取消後の保有と余力更新まで自動追随することを受入条件に含める。
- 判定に必須の板・口座状態・イベント等が自動取得できない場合は未確認としてGO禁止。本人確認済みフラグや日時の自動代入で解決しない。
- 価格・VWAPの鮮度はTradingViewの観測時刻で評価。元の「SBI確認日時」は価格確認の必須手入力としては引き継がない。SBIの口座状態とTradingView価格を別々の出典で管理し、他社価格をSBI確認済みと表記しない。

## 次の実装順序

1. 既契約・既存接続で価格/VWAP/板/SBI余力・保有・約定の正規自動取得が可能か確認し、取得できる項目と欠落項目を明示する。追加契約・課金は無断で行わない。
2. 候補資格と市場イベントをクラウド側で更新し、当日の候補/期限を自動連携する設計を確定。TradingViewの入力を毎朝本人が更新する方式は完成条件を満たさない。
3. 価格・イベント・口座状態の観測時刻を束ねた自動判定を別ブランチで実装。既存の手動ゲートは検証・復旧用として維持。
4. 買い/利確/損切り/異常の通知を重複抑止・失効付きで試験し、本人入力なしの場中運転を実測する。
5. データと履歴を揃え正式バックテスト・未使用期間検証へ進む。取得できない履歴や板を推測値で合格扱いにしない。
