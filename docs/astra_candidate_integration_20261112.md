## 本番へ反映済み

実戦候補TOP10!B2:G11、O2:Q11の90セルは、監視ランキングの4～100行（97銘柄）だけを参照していた。監視データ自体は4～103行に100銘柄あり、末尾3銘柄が候補抽出から漏れる状態だった。参照終端を103行へ修正した。その他の数式、書式、入力、GO停止ゲートは変更していない。

検証用ブックの独立タブで、100番目の銘柄のScoreを999にした合成データを使用。旧式では6855、新式では末尾の5599が選ばれ、不具合と修正をGoogle Sheetsの再計算で確認。本番反映後に90セルの数式を読み戻し、予定差分との一致とエラーなしを確認した。現在のTOP10の結果値は修正前後で同じで、SBI連動の10件はすべてGO禁止。通常倍率のGoogle表示も確認済み。

修正生成器：`astra/top10_range_patch.py`。想定のセル配置・数式・検証ルールから変わっていた場合は修正要求を生成しない。バックアップと適用要求は引き継ぎ資料に保存。

## 開発ブランチに実装

`astra/candidate_projection.py` は、監視ランキング100銘柄・TOP10・イベント表の取得済みスナップショットを読み、手動SBI価格や確認チェックを使わずに候補条件を照合する。

- 100銘柄の集合、重複、最新完了市場日、TOP10と元ランキングの一致、全100銘柄からの上位抽出を確認。
- A/A+、100株単位、推奨株数、3 JPX営業日以内の個別/共通イベントを確認。
- イベントの残日数や「終了」の表示が古くても、実日付から再計算。
- 取得が5分以上古い、取得区間が30秒を超える、将来日時、列名変更、欠損・競合などは停止。
- 取得時刻をランク更新確認やイベント調査完了へ読み替えない。空のイベント表でも調査完了にはしない。
- 出力は条件照合結果であり、GO・実注文・通知は実行しない。

実行例：

```sh
python3 -m astra.candidate_projection --bundle snapshot.json
python3 -m unittest discover -s astra/tests -v
```
