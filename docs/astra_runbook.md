## 候補通知を受けたとき

- 候補通知はGOではない。SBIで銘柄、当日現在値、VWAP、出来高継続、上ヒゲ、ギャップ、板、売買可能状態を再確認する。
- 現在値はVWAP以上。損切りは現在値より下。現金余力と既存保有の損失予算を差し引いて100株単位で計算する。
- SBI確認日時と価格・4チェックの入力証拠は当日かつ5分以内。最終GO表示は最も古い入力から最大4分。価格が動いたら再入力・再計算する。
- すべて満たした場合だけ本人がSBIで手動発注し、損切りを設定。自動発注やWebhook注文は使わない。

## 発注前資金確認の使い方

1. SBI連動_v77に現在値・当日VWAP・出来高継続・上ヒゲ小・ギャップOK・板OKを入力し、最後にL列の確認を単独でタップする。本人の確認を自動で代入しない。
2. 発注前資金確認のB3で同じ銘柄を選ぶ。選び直すとB10:B18は消去される。
3. B10に入力対象コード、B11に損切り、B12に今回の許容損失、B13に保有・未約定分を差し引いた損失予算、B14にSBI現物余力、B15に1株あたり往復手数料+スリッページを入力。0円の費用も明示する。
4. B16に調査済みの日付（次の3JPX営業日以上）、B17に公式根拠URL、B18に個別と重要マクロイベントの調査メモを入力する。登録なしを安全の根拠にしない。
5. B34「本人が確認」を単独タップ。計算上限B23だけではGOではない。B26の判定、B35の照合日時、B36の有効期限、B37の照合済み株数を確認する。
6. GO候補でも、注文直前にSBIの最新価格・板・余力・損切り注文を本人が確認する。期限切れ、表示と現在値の相違、追加材料があれば見送って再確認する。

新規候補の確認時間は09:05–11:25 / 12:30–14:55。昼休み、休場日、時間外はGO禁止。信用取引の余力・金利・保証金管理には未対応のため、この資金フォームは現物用。

## iPhone通知の合格確認（単発受信済み・実条件は未確認）

| 確認 | 合格の証拠 |
|---|---|
| 同一アカウント | TradingViewのアプリとブラウザが同じアカウント |
| 通知許可 | iOSのTradingView通知許可、ロック画面表示を本人が確認 |
| アラート作成 | 候補版のalert()、アプリ通知を選択。保存時の入力を記録 |
| 実機到達 | 単発テストは本人確認済み。実銘柄条件の発生/受信時刻、銘柄、重複は別途記録 |
| 集中モード | 実際に使う集中モード/消音/ロック状態で受信を確認 |
| 翌日失効 | 前日のA/A+設定では候補通知を出さないことを確認 |
| 条件変更 | 入力変更後にアラートを再作成し、新しい設定で動作を確認 |

条件が来なければ通知が来ない。未発火だけを通知成功の証拠にしない。実通知のためだけに売買条件を緩めない。

## 引け後と異常時

日足の確定は現在の互換運用では18時以降を目安に扱う。日次データ・候補/非候補理由・イベント出典/確認時刻・SBI確認を記録する。
データ遅延、未知の休日、欠損、別銘柄、古い確認時刻、リスク超過はGO禁止。バックテストの好成績でこれらを上書きしない。
本番移行時は変更前の式/コード/データを保存し、取込失敗時は成功表示へ進めず、前回データと停止状態を維持する。
