# iPhone・iPad運用：最新状態

2026-11-12更新。価格はTradingView、注文はSBIで本人操作。勤務中に毎回Sheetへ確認入力する方式は最終要件ではない。

現在動くもの：100銘柄の日足同期、5分間隔の候補照合、15分間隔で確認する判定履歴、既存朝・引け後処理、TradingViewの7011技術監視アラート設定。

2026-11-12の本人指示で、TradingView利用条件は本人判断でクリアした前提とし、SBI APIによる残高取得は新規候補の要件から外した。提供元の書面許諾が取得できた、という事実認定ではない。

新規候補は「設定」B2の入力予算とB3の1取引リスク率で計算する。今回の実読値は100万円と1.5%。SBIの実残高と表記しない。設定値が変われば試算は更新する。本人入力の更新まで同額を使うが、未確認の約定・売却益を加算しない。

追加画面「入力予算判定」は縦3列の10候補試算。終値と既存損切り率を使用し、費用と滑りの初期仮定は往復0.2%（B5で変更可）。上位候補から共通予算を配分する。通知の予約台帳や当日価格とは未接続であり、現段階の画面は実戦GOを出さない。

未完成：A/A+・当日TV価格・板・イベント・入力予算の本番統合GO、実保有に基づく利確/損切り通知、実条件のiPhone到達の一連検証、正式バックテスト。技術観測通知は売買指示ではない。

GO禁止が出たら発注しない。表示の取得時刻を、板や余力が確認された時刻と混同しない。候補照合は有効期限10分。データ停止時は過去候補を無効化する。

旧版のSBI連動・本人確認フォームは互換維持のため残してあるが、全自動運用の完成版として案内しない。自動で本人確認済みに書き換えない。

復旧：新しい候補照合だけを止める場合はastraCandidateTick、新しい履歴だけならastraRankHistoryTickを停止。既存syncJapaneseStocksV76、resetSbiV77Daily、handleSbiV77Editは維持する。

SBI APIやTradingView許諾の再問い合わせを開発の停止条件にしない。必要なのは認証済みWebhook受信先、実イベント・板の取得経路、通知の接続検証。新規契約・課金・認証情報の入力は本人の操作とする。

input_budget.py の予約台帳は通知候補の予算拘束であり、保有・約定台帳ではない。日替わり・期限切れ・入力予算変更で自動解放しない。通知見送り等の本人確認によってのみ解放する。価格の悪化や未登録注文は推定できない。新規通知だけで実保有を作らない。
