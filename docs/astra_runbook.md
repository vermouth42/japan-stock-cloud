# iPhone・iPad運用手順（開発段階）

本番運用開始前の手順書。Pine 2本のコンパイルは確認済み。端末通知の実測と本番の安全連携が未完了のため、完成済みとは扱わない。

## 毎朝

1. 監視100銘柄、4,500行、重複0と、直近完了営業日を確認する。「同期成功」の文字だけでは鮮度の証明にならない。
2. A/A+だけを新規候補にする。現在値で100株の買付余力と損切り損失を計算し、余力不足なら候補から外す。
3. 個別決算とCPI/雇用統計/FOMC等の重要イベントを確認。3JPX営業日以内または調査範囲不明なら見送る。
4. 検証用Pineの銘柄・A/A+・当日・株数・損切り・予算を入力する。初期状態の通知はOFF。設定変更後の既存アラートは再作成する必要がある。

## 候補通知を受けたとき

- 候補通知はGOではない。SBIで銘柄、当日現在値、VWAP、出来高継続、上ヒゲ、ギャップ、板、売買可能状態を再確認する。
- 現在値はVWAP以上。損切りは現在値より下。現金余力と既存保有の損失予算を差し引いて100株単位で計算する。
- SBI確認日時は当日であること。開発中の検証関数はさらに5分以内を仮条件としている。価格が動いたら再計算する。
- すべて満たした場合だけ本人がSBIで手動発注し、損切りを設定。自動発注やWebhook注文は使わない。

## iPhone通知の合格確認（未実施）

| 確認 | 合格の証拠 |
|---|---|
| 同一アカウント | TradingViewのアプリとブラウザが同じアカウント |
| 通知許可 | iOSのTradingView通知許可、ロック画面表示を本人が確認 |
| アラート作成 | 候補版のalert()、アプリ通知を選択。保存時の入力を記録 |
| 実機到達 | 発生時刻と受信時刻、銘柄、重複有無を実際に記録 |
| 集中モード | 実際に使う集中モード/消音/ロック状態で受信を確認 |
| 翌日失効 | 前日のA/A+設定では候補通知を出さないことを確認 |
| 条件変更 | 入力変更後にアラートを再作成し、新しい設定で動作を確認 |

条件が来なければ通知が来ない。未発火だけを通知成功の証拠にしない。実通知のためだけに売買条件を緩めない。

## 引け後と異常時

日足の確定は現在の互換運用では18時以降を目安に扱う。日次データ・候補/非候補理由・イベント出典/確認時刻・SBI確認を記録する。
データ遅延、未知の休日、欠損、別銘柄、古い確認時刻、リスク超過はGO禁止。バックテストの好成績でこれらを上書きしない。
本番移行時は変更前の式/コード/データを保存し、取込失敗時は成功表示へ進めず、前回データと停止状態を維持する。
